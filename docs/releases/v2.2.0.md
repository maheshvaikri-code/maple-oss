# Release checklist — 2.2.0

**Date:** 2026-09-05 · **Gate:** G6 · **Owner:** Release Manager
**Scope:** 15 commits, 7 ADRs (162–168) since `v2.1.0`.

## What this release is

2.2.0 continues what 2.1.0 started: **every change closes a case where
something reported success it had not achieved.** 2.1.0 fixed controls that
silently did nothing. 2.2.0 fixes the same class one layer out — numbers that
never left the process, shutdowns that discarded work while returning cleanly,
configuration accepted and ignored, waits that never woke, and a transport that
had never once connected.

It also changes what MAPLE *is*: `FileBroker` makes it multi-process on one
host, so the broker contract is now implemented twice.

## Breaking changes

Stated first because they are the reason to read the notes. Each corrects
behaviour that was wrong, but code written against the old behaviour will
notice.

| Change | What breaks |
| --- | --- |
| **`Config` validates at construction** | An empty `agent_id`, a non-positive `max_queue_size`, or an unsupported/mistyped `broker_url` scheme now raises `ConfigurationError` where it was silently accepted |
| **`stop()` drains and returns `int`** | It can take longer (bounded by `drain_timeout`, default 5s, instant when idle) and returns the count it could not drain. `stop(drain_timeout=0)` restores the old timing |
| **`receive()` can return `AGENT_STOPPED`** | A parked receive used to block forever after `stop()`; it now returns a typed error |
| **`Agent.executor` is gone** | The per-agent `ThreadPoolExecutor` was never used. Nothing in the tree referenced it |
| **NATS refuses unroutable sends** | With presence, a message to a receiver nobody serves is counted and dead-lettered rather than published into a subject with no listener |
| **Broker scheme matching is case-insensitive** | `NATS://host` now reaches the fail-closed path instead of silently falling back to the in-process broker |

**On versioning:** strict semver would call these a major. `3.0.0` is reserved
in [`docs/roadmap.md`](../roadmap.md) for multi-*host* operation, which this is
not, so the correction ships as a minor with the breaks documented here and in
the changelog.

## Publication

**Escalation (doctrine §5): publishing to PyPI is external and irreversible.**
It happens only on explicit instruction.

A pushed tag does **not** publish — the workflow's `GITHUB_TOKEN` cannot
trigger it. Publication is a manual dispatch:

```powershell
gh workflow run publish.yml -f target=pypi
```

- [ ] Tag `v2.2.0` pushed
- [ ] `publish.yml` dispatched to PyPI
- [ ] GitHub Release created with assets **verified byte-identical to PyPI**
      by SHA-256 (2.1.0's local `dist/` differed from the published artifacts;
      download from PyPI rather than attaching a local build)
- [ ] Fresh-virtualenv install checked before announcing

## What is deliberately not in this release

- **NATS is not conformant.** Presence closed routability and undeliverable
  reporting; backpressure remains, and it is two decisions rather than work —
  core NATS holds no queue to be full, and the contract expects `send()` to
  raise where that transport returns a `Result`.
- **Multi-host.** `FileBroker` crosses processes on **one host**. Nothing here
  crosses hosts.
- **The flaky loopback tests.** A few autonomy tests that start a real HTTP
  server flake under load on Windows. Reproduced on an unmodified tree; a test
  defect, not a runtime one.
- **`receive()` competing with the handler loop.** Both consume the same queue,
  so `receive()` is unreliable on a started agent. A contract decision, not a
  defect fix.
