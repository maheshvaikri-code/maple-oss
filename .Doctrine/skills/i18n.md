# Skill: Internationalization

**Scope.** Everything a locale changes: user-facing text, plurals, dates,
numbers, currency, collation, text direction, and the translation pipeline.

## Principles
- No hardcoded user-facing strings. Every string lives in a resource file
  under a stable key; code references keys, never English sentences.
- Grammar is not arithmetic: plurals, gender, and word order differ per
  language. ICU MessageFormat (or equivalent) handles it; concatenation
  cannot.
- Locale formatting is platform work: dates, numbers, currency, and
  collation come from platform/ICU APIs, never hand-rolled tables.
- Translations are content, not code — but they ship through review like
  code, because a bad string is a bad release.

## Defaults
- Source-of-truth locale named explicitly (e.g. `en-US`); all others
  derive from it. Keys are stable identifiers, not the English text.
- UTF-8 everywhere: files, wire, storage. Normalize (NFC) on input;
  compare and collate locale-aware, never by byte.
- Locale fallback chain declared: `fr-CA` → `fr` → source locale. A
  missing key falls back loudly in dev, quietly in prod, never crashes.
- RTL supported structurally: logical CSS properties
  (`margin-inline-start`, not `margin-left`), `dir` set from locale,
  layout exercised in at least one RTL locale.
- Pseudo-localization runs in CI: accented, ~40%-longer strings catch
  hardcoded text and layout breakage before a translator ever does.

## Do
- Give translators context: a comment per key — where it appears, what
  each placeholder holds — travels with the string.
- Use ICU plural/select for anything counted or gendered:
  `{count, plural, one {# item} other {# items}}`.
- Format at the display edge: store UTC instants and canonical numbers;
  render per the viewer's locale.
- Leave room: German runs ~30% longer, and buttons truncate first.

## Don't
- Don't write `"item" + (n > 1 ? "s" : "")` — several languages have more
  than two plural forms, and some have one.
- Don't build sentences from translated fragments; word order betrays you
  in the first non-English locale.
- Don't embed values or markup in translations without named placeholders.
- Don't sort user-visible lists with byte comparison.
- Don't let tests or screenshots assert on translated copy; assert on keys.

## Review checklist
- [ ] No user-facing string literals in code; keys stable and commented
- [ ] Plurals/gender via ICU MessageFormat; zero concatenated sentences
- [ ] Dates/numbers/currency/collation via platform APIs only
- [ ] UTF-8 end to end; input normalized; fallback chain defined
- [ ] RTL: logical properties throughout, one RTL locale rendered
- [ ] Pseudo-localization pass green in CI

## Common failure modes
The English sentence frozen into a key name and now wrong in English too;
`toFixed(2)` currency; the plural that broke in Polish; RTL "support"
that mirrored the icons but not the layout; translations merged to main
without a human ever reading them.
